# Agent tools

Read before adding or changing an agent tool: off-lock dispatch, and the marker tools.

A tool added, renamed or removed also updates its copies (the tool trigger of the Staleness sweep in `CLAUDE.md`) and moves the request-size numbers (`crates/ai/tests/request_size.rs`, `docs/agents/providers.md`).

## Off-lock tools

- Agent tools run off the store lock when `Tool::runs_off_the_lock()` is true (#421): `tools::Shared::dispatch` runs them on a `Store::stage()` handle and commits only if the head is unchanged. A lost race re-runs the tool on the new head, at most one re-run (two off-lock runs in all), and if both lose, a third run is made under the locks. A re-run is refused, with a `ToolResult::Error` for the model, when the user's edit changed a track the call names by position (a removal, or an undo that brings one back) or that track's clips, because the arguments no longer describe the session. The default is false, and `crates/tools/tests/off_lock_tools.rs` pins the list, so opting a tool in is a reviewed change. An off-lock tool reports no `progress` unless that file's `ALLOWED` list names the spelling, with its reason (`select_region`'s selection; `transcribe`'s windows, #384).

## Marker tools

- **Marker tools (#766 item 1; `crates/tools/src/tool/markers.rs`).** `find_markers` (read-only, on `READ_ONLY`; pages through `list_session::paged`, the lines of `session_lines::marker_line_with_id`), `add_markers` (a list, or `every` seconds from `from` to `to`, each time `from + i * every`), `edit_markers` and `delete_markers`; at most 500 items a call (`MAX_BATCH`), all or nothing, one node a call, none when nothing changes. What a label may be is `session::check_marker_time` / `check_region` and how an edit is read is `session::AnnotationEdit` (`validate`, `resolve`), which the window's `add_marker` / `update_marker` and these four tools call: change the rule there, not in a copy. That agreement covers these tools and the window only: `label` has its own looser rule and still takes a negative time. `find_markers` reads `from`/`to` as overlap, `delete_markers` as wholly inside (a region that spans the range is not "between" it), and both take `name` as part of a name, any case; a result or refusal repeats a name or id cut to 60 characters (`echo`). Of #766's other items, per-marker export (item 3) and chapter files (item 4, `export_labels`'s formats) are built; marker-driven edits (item 2) are not. The four tools add 1,935 B to the full request (`request_size.rs`) and 57 B of names to the slim names line; `MCP_ROOM_BYTES` in `tool_selection.rs` stays 400, which the names line leaves since its compaction landed (#897); keep the room by shortening descriptors or names, not by raising `SLIM_NAMES_BUDGET_BYTES`, which would break the 500 B MCP headroom. `find`, `edit` and `delete` are in `GENERIC_TOKENS`, so only the word "marker" sends these tools to a slim (Ollama) request.
- **Per-region export (#766 item 3; `crates/tools/src/tool/export_multiple.rs`)** is `export_multiple` with `regions: true` in place of `track_indices` (one or the other), not a tool of its own: it shares that tool's `output_dir` rule (relative, no `..`), its WAV-only format and its file naming, and keeps the tool count. One WAV per `AnnotationKind::Region` of the head, named `<n>_<sanitised name>.wav` with `n` counting the regions in time order from 1 (zero-padded to the widest) and the name cut to 60 characters, each the render of the whole session over the region's seconds (`Engine::render_to_wav` with a `range`, as `render_final` does), so mute, solo, buses and the master are as a full render has them. Point markers are left out and counted (`skipped_markers`), as is a region with a time that is not finite (`skipped_not_finite`; a stored node cannot hold one, since JSON has no NaN, so its test is a unit test of `plan_regions`). The session's end is where the render stops (`mix_length_frames`: the furthest clip over the tracks the renderer's plan mixes, so a muted track running on does not count). A region past it is cut there (`clamped`); one wholly past it, or no region at all, refuses the call. Every file is planned and checked by `destination::refuse_project_audio` before the first is written. It adds 119 B to the full request and the Responses request (`request_size.rs`) and nothing to a slim one; "each" or "every" with "export" already sends it to a slim request. `crates/tools/tests/export_regions.rs` and `render_over_source.rs` pin it.
