# Agent tools

Read before adding or changing an agent tool: off-lock dispatch, and the marker tools.

A tool added, renamed or removed also updates its copies (the tool trigger of the Staleness sweep in `CLAUDE.md`) and moves the request-size numbers (`crates/ai/tests/request_size.rs`, `docs/agents/providers.md`).

## Off-lock tools

- Agent tools run off the store lock when `Tool::runs_off_the_lock()` is true (#421): `tools::Shared::dispatch` runs them on a `Store::stage()` handle and commits only if the head is unchanged. A lost race re-runs the tool on the new head, at most one re-run (two off-lock runs in all), and if both lose, a third run is made under the locks. A re-run is refused, with a `ToolResult::Error` for the model, when the user's edit changed a track the call names by position (a removal, or an undo that brings one back) or that track's clips, because the arguments no longer describe the session. The default is false, and `crates/tools/tests/off_lock_tools.rs` pins the list, so opting a tool in is a reviewed change. An off-lock tool reports no `progress` unless that file's `ALLOWED` list names the spelling, with its reason (`select_region`'s selection; `transcribe`'s windows, #384).

## Marker tools

- **Marker tools (#766 item 1; `crates/tools/src/tool/markers.rs`).** `find_markers` (read-only, on `READ_ONLY`; pages through `list_session::paged`, the lines of `session_lines::marker_line_with_id`), `add_markers` (a list, or `every` seconds from `from` to `to`, each time `from + i * every`), `edit_markers` and `delete_markers`; at most 500 items a call (`MAX_BATCH`), all or nothing, one node a call, none when nothing changes. What a label may be is `session::check_marker_time` / `check_region` and how an edit is read is `session::AnnotationEdit` (`validate`, `resolve`), which the window's `add_marker` / `update_marker` and these four tools call: change the rule there, not in a copy. That agreement covers these tools and the window only: `label` has its own looser rule and still takes a negative time. `find_markers` reads `from`/`to` as overlap, `delete_markers` as wholly inside (a region that spans the range is not "between" it), and both take `name` as part of a name, any case; a result or refusal repeats a name or id cut to 60 characters (`echo`). Items 2 to 4 of #766 (marker-driven edits, per-marker export, chapter files) are not built. The four tools add 1,935 B to the full request (`request_size.rs`) and 57 B of names to the slim names line; `MCP_ROOM_BYTES` in `tool_selection.rs` stays 400, which the names line leaves since its compaction landed (#897); keep the room by shortening descriptors or names, not by raising `SLIM_NAMES_BUDGET_BYTES`, which would break the 500 B MCP headroom. `find`, `edit` and `delete` are in `GENERIC_TOKENS`, so only the word "marker" sends these tools to a slim (Ollama) request.
