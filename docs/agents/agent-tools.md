# Agent tools

Read before adding or changing an agent tool: off-lock dispatch, and the marker tools.

A tool added, renamed or removed also updates its copies (the tool trigger of the Staleness sweep in `CLAUDE.md`) and moves the request-size numbers (`crates/ai/tests/request_size.rs`, `docs/agents/providers.md`).

## Off-lock tools

- Agent tools run off the store lock when `Tool::runs_off_the_lock()` is true (#421): `tools::Shared::dispatch` runs them on a `Store::stage()` handle and commits only if the head is unchanged. A lost race re-runs the tool on the new head, at most one re-run (two off-lock runs in all), and if both lose, a third run is made under the locks. A re-run is refused, with a `ToolResult::Error` for the model, when the user's edit changed a track the call names by position (a removal, or an undo that brings one back) or that track's clips, because the arguments no longer describe the session. The default is false, and `crates/tools/tests/off_lock_tools.rs` pins the list, so opting a tool in is a reviewed change. An off-lock tool reports no `progress` unless that file's `ALLOWED` list names the spelling, with its reason (`select_region`'s selection; `transcribe`'s windows, #384).

## Marker tools

- **Marker tools (#766 item 1; `crates/tools/src/tool/markers.rs`).** `find_markers` (read-only, on `READ_ONLY`; pages through `list_session::paged`, the lines of `session_lines::marker_line_with_id`), `add_markers` (a list, or `every` seconds from `from` to `to`, each time `from + i * every`), `edit_markers` and `delete_markers`; at most 500 items a call (`MAX_BATCH`), all or nothing, one node a call, none when nothing changes. What a label may be is `session::check_marker_time` / `check_region` and how an edit is read is `session::AnnotationEdit` (`validate`, `resolve`), which the window's `add_marker` / `update_marker` and these four tools call: change the rule there, not in a copy. That agreement covers these tools and the window only: `label` has its own looser rule and still takes a negative time. `find_markers` reads `from`/`to` as overlap, `delete_markers` as wholly inside (a region that spans the range is not "between" it), and both take `name` as part of a name, any case; a result or refusal repeats a name or id cut to 60 characters (`echo`). Of #766's other items, per-marker export (item 3), chapter files (item 4, `export_labels`'s formats) and marker-driven edits (item 2, below) are built. The four tools add 1,935 B to the full request (`request_size.rs`) and 57 B of names to the slim names line; `MCP_ROOM_BYTES` in `tool_selection.rs` stays 400, which the names line leaves since its compaction landed (#897); keep the room by shortening descriptors or names, not by raising `SLIM_NAMES_BUDGET_BYTES`, which would break the 500 B MCP headroom. `find`, `edit` and `delete` are in `GENERIC_TOKENS`, so only the word "marker" sends these tools to a slim (Ollama) request.
- **Chapter files (#766 item 4; `crates/tools/src/tool/export_labels.rs`).** `export_labels` takes `format`: `audacity` (the default, byte-for-byte the text it returned before), `podlove_json` (Podlove Simple Chapters, https://podlove.org/simple-chapters/, as the JSON array of `{start, title}` that https://github.com/podlove/chapters writes, `start` in Normal Play Time `HH:MM:SS.mmm`) or `cue` (a CUE sheet as GNU ccd2cue documents it, https://www.gnu.org/software/ccd2cue/manual/html_node/CUE-sheet-format.html: `TITLE`, a `FILE` line named by `file_name`, then `TRACK nn AUDIO`, `TITLE` and `INDEX 01 mm:ss:ff` at 75 frames a second, minutes past 99 as they are, at most 99 tracks with the rest counted in `omitted`, titles cut to 80 characters with `"` written `'` and control characters as spaces). The chapter formats sort by start (stable), take a region's start, read a negative time as 0 and leave out a time that is not finite. `file_name` defaults to `audio.wav`; it is refused when blank or given with another format. It stays read-only (on `READ_ONLY`) and writes no file: the text comes back in `labels`. `crates/tools/tests/chapter_export.rs` pins each format's text; the formats add 225 B to the full request.
- **Per-region export (#766 item 3; `crates/tools/src/tool/export_multiple.rs`)** is `export_multiple` with `regions: true` in place of `track_indices` (one or the other), not a tool of its own: it shares that tool's `output_dir` rule (relative, no `..`), its WAV-only format and its file naming, and keeps the tool count. One WAV per `AnnotationKind::Region` of the head, named `<n>_<sanitised name>.wav` with `n` counting the regions in time order from 1 (zero-padded to the widest) and the name cut to 60 characters, each the render of the whole session over the region's seconds (`Engine::render_to_wav` with a `range`, as `render_final` does), so mute, solo, buses and the master are as a full render has them. The counts below (`skipped_markers`, `skipped_not_finite`, `clamped`) are fields of a successful result; a refusal carries none. Point markers are left out and counted (`skipped_markers`), as is a region with a time that is not finite (`skipped_not_finite`; a stored node cannot hold one, since JSON has no NaN, so its test is a unit test of `plan_regions`). The session's end is where the render stops (`mix_length_frames`: the furthest clip over the tracks the renderer's plan mixes, so a muted track running on does not count). A region past it is cut there (`clamped`); one wholly past it, or no region at all, refuses the call. Every file is planned and checked by `destination::refuse_project_audio` before the first is written. It adds 126 B to the full request and the Responses request (`request_size.rs`) and nothing to a slim one; "each" or "every" with "export" already sends it to a slim request. `crates/tools/tests/export_regions.rs` and `render_over_source.rs` pin it.
- **Marker-driven edits (#766 item 2; `crates/tools/src/tool/edit_at_markers.rs`).** One tool, `edit_at_markers { action, track, markers, width? }`, `action` one of `cut`, `delete`, `silence`, `split`, `join`; `markers` are names (whole, any case) or ids, at most 500 (`MAX_BATCH`). It adds no audio code: `cut` is `cut_range::cut_span`, `silence` is `silence_region::silence_spans`, `split` is `split_clip::split_track_at` over `split_at`, `join` is `join_clips::join_run`, so the same span under a marker and by its time leaves the same session (`tests/marker_audio_edits.rs` compares the tracks and labels to the time-range tool's). Change a time edit in those functions, not in a copy. **Why one tool and not a `marker` argument on the four range tools:** their arguments differ (samples, seconds, a clip index, a clip run), so each would need `required` loosened and a `marker`/`markers` pair and a `width` added (four schemas, 4 x about 250 B of full request each, and a model that must know which of two ways each tool takes); one tool is 852 B of the full request (883 B of the Responses one) and 16 B of the slim names line, and the existing tools' schemas and their `runs_off_the_lock` are unchanged. A marker is a region's `[start, end)` or, for a point marker, `[time, time + width)`; a point without `width` is refused for every action but `split` (a split needs only a time, so a region splits at both edges and `width` is ignored). `delete` removes the span and leaves the gap (nothing after it moves, no label moves); `cut` closes it. **Sync-lock** follows `cut_range`: `cut` and `delete` take the same seconds from the other tracks when it is on (`sync_other_tracks`, each in its own clip rate, #673), labels always move on a cut (`remap_after_cut`, #203), a locked track's transcript with it (`Moved::sync_locked`, #925); `silence`, `split` and `join` move nothing and, like their tools, do not follow it. A cut region marker collapses and is dropped with its audio (`dropped_labels`); a point marker at the cut's first instant stays at the seam, as `cut_range` keeps a mark on a cut's edge. Several markers are one node (one undo), worked latest first so an earlier span is still where it was; **two overlapping spans are refused** rather than merged (touching ones are fine), as is an unknown name, a name that fits two markers (the refusal lists the ids), a span past the track's end (`cut_range`'s message) and a `split` that splits nothing; a refusal appends no node. `join` takes the clips lying wholly under the span, needing two or more in one unbroken run. The tool is not `runs_off_the_lock` (it reads markers and several tracks and the join may write a file; opting in is a reviewed change, `off_lock_tools.rs`), it is held by Plan first (`mutates`), and `edit_markers` still means the markers themselves, not the audio.
