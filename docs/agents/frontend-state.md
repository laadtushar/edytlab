# Frontend state and webview quirks

Read before touching undo/redo, the head trail, lane controls, the session module (`useSession`), the window's mix, WaveSurfer, keyboard or wheel handlers, or confirm/prompt dialogs.

## The session module

- `apps/desktop/src/hooks/useSession.ts` is the only way the window changes the session (ADR 0001, #713). It has two operations, both mutations in one TanStack Query scope, `'session'`, so they run one at a time in the order they were made (#498):
  - `edit(name, args, { hold })`: a command that returns a new head (a track control, a marker, a template, a transcript cut, a load, naming a node). The head it returns is adopted inside the turn.
  - `move(request)`: `undo`, `redo`, `setHead` (Set as head), `acceptB`, `open` (a project), `saveAs` and `reconcile` (a punch-in has landed). The session moved by itself, so every held lane control is let go of and every read is made again. `agent://node-created` is the assistant's move and is heard in the module itself.
- **A new session-changing command is one entry** in `apps/desktop/src/lib/sessionCommands.ts` (`edits`, or `moves`). An `edits` entry's type has no default for what head it returns (`head`) or which reads it changes (`reads`, from `lib/sessionReads.ts`), so a command that drops its head (#232) or names no reads does not compile. Its sample goes in `SAMPLES` in `useSession.session.test.tsx`, which is typed to need one per entry and checks that each entry's head is adopted.
- **Only `useSession` may import `lib/sessionCommands.ts` or `hooks/useSessionHead.ts`** (`__tests__/sessionBoundary.test.ts`; the app has no ESLint, so it is a vitest import test). `tauri-bridge.ts` does not export the session commands, and no other file may name their IPC commands, so there is no way to send one outside the line, to drop the head it returns, or to move the head from a handler. This replaced the two regex scans of `App.tsx` (`headIsApplied`, `sessionQueueCoverage`); `findViolations` is tested on a file that breaks each rule. Do not widen the allowed importers: take the operation from `useSession`, and hand a component a prop instead of a command.
- **Reads are queries under `['session', …]`** (`lib/sessionReads.ts`): tracks, graph, labels (`useMarkers`), transcript (`useTranscript`), render warnings (`useRenderWarnings`, per node). A turn cancels the reads it can change before it runs and asks for them again when it settles, from its entry's `reads`; a failed edit is read back too, so a refused value goes back to the session's. A turn does not wait for its reads, so the next edit goes out at once. The track read is `structuralSharing: false`, so every adopted read hands out new `TrackSummary` and `clips` references (the lanes re-sync on identity). `graphVersion`, `refreshKey` and numbered reads are gone: to read something again, invalidate its key.
- The mix is stale by comparison only: `mixIsStale` compares the mix's node with the node shown. A render also carries `useSession().edition`, which goes up when an edit adopts a head, the assistant makes a node, a project opens or a punch lands; a render from an older edition is no mix at all (the "preview not rendered" hint), so no handler clears it by hand. Undo, redo, Set as head and Accept B do not count: the mix of the node they leave is still that node's, and the "preview out of date" badge says it is not the one shown.
- Not built: ADR 0001 also has the module record the assistant turn's start and end. The backend emits no turn-start event, so there is nothing to record it from; the assistant's moves, which are what held controls need, arrive as `agent://node-created` and are handled as moves.

## Undo, redo and the head trail

- Undo/redo follow the path the user took (`apps/desktop/src/lib/headTrail.ts`, held by `useSessionHead`, which `useSession` composes), never `node.parent` alone. Node ids hash state only, so a revisited state keeps its first parent (#398). Every frontend head move goes through `useSessionHead`'s `setHeadLocal` (an edit, the assistant, Set as head, Accept B) or `resetHead` (opening a project), and only `useSession` can call them, from `edit`, `move` and `agent://node-created`. `GraphView` never calls `set_head_to` itself (Set as head is the `setHead` move App sends, `onSetHead`), and anything showing session state is a query that the turn that moved the head reads again, since `set_head_to` emits no event. The History graph is the `graph` query, read by `GraphView` itself: it is invalidated by every head-moving turn and project opening, by `agent://done` (a `name_node` label moves no head), and by every `forgetRemoved` (a compaction ending, a refused undo). A click on a graph bubble is a preview, not a head move (#522): it lives in `useGraphPreview`, apart from `head`, so the saved path only follows moves the store made, and it reads nothing; do not make it a move. The window keeps the undo rule and the store keeps the file (#568): move the rule into the store only for a client that does not run this UI, two tabs or users on one project, an agent tool that undoes along the path, or another head-desync bug. A compaction deletes nodes the path can name, so `forgetRemoved` drops them when `compact_session` ends (a turn in the line), and undo/redo skip, rather than retry, a step the store refuses for a node its `get_graph` list no longer has (#595).
- The path survives a restart (#453): `useSessionHead` saves it with the project (`save_head_trail` -> `.audiograph/trail.json`, `crates/session/src/trail.rs`) after every move, and reads it back (`get_head_trail`) at launch and in `restoreView`, whose answer the `open` move hands to `resetHead(head, saved)`; it is taken only if it ends at the head the project opened on. The save goes through `lib/trailWriter.ts`, never through the line: one in flight, the newest replaces any waiting, and no edit waits for the disk. A missing or corrupt file is an empty path and never blocks opening a project. A new head-moving path must be a `move` or an `edit` so the file stays in step.

## Lane controls

- A lane control the user has set (gain or pan slider, mute, solo) is the user's until the session confirms it (#596). `Timeline` copies whatever `tracks` it is handed into its lanes, so a track-list read requested before the user's next input and landing after it used to put the older value back: a flicker, or a lost key tap, since the key-up then committed the value the session already held and `commitSlider` sent nothing. The held value is not state of its own (`lib/heldControls.ts` is only the overlay): it is the slider's input value before its commit (`holdInput`, a draft in `useSession`), then the `variables` of the edit that commits it (`edit(..., { hold })`), then those of a `confirm` mutation that is pending until the first track read asked for after the commit was answered has landed. Failed, cancelled or obsolete reads confirm nothing, because each turn cancels the reads in flight when it starts. `useSession().tracks` is the list with the held values laid over it (what the lanes draw), `sessionTracks` the session's own, which a commit compares against; `sentValue` (the last value sent and not yet confirmed) is what makes 0 -> -3 -> 0 send the final 0, and `dropInput` is a release or blur that needed no commit. A new lane control that shows its value ahead of its commit passes `hold` to `edit` and, if it has an input event, calls `holdInput`. Every `move`, and `agent://node-created`, lets go of everything held before it (`epoch`): undo, redo, Set as head, A/B compare's Accept B, opening a project, Save As and the assistant's edits. A refused commit is handed back like any other, with the session's value. `App.laneControls.test.tsx` pins it in jsdom (undo, opening a project) and `e2e/lane-readback.spec.ts` with real key events; `App.sessionMoves.test.tsx` pins Accept B and the assistant's edits, `useSession.session.test.tsx` the module itself, and `e2e/accept-b.spec.ts` Accept B in Chromium.

## The window's mix

- The mix the window plays is held in the preview cache (#607, #635). The transport loads its file again whenever the timeline mounts (a switch to the Graph or Transcript tab and back), and an entry the agent's renders, an audition or a compare had evicted meanwhile was a "Could not load the mix". So the window's `render_preview` command (Play, Preview and a graph preview) holds the entry it returns in `AppState::window_mix` (`window_mix.rs`, a `tools::preview_cache::Held`): the next `render_preview` replaces the hold, a project change releases it, a render that fails changes nothing, and the agent's tools render into the same cache with no hold of their own. A held entry is outside the cap, so `previews/` is bounded by the cap plus the A/B compare's pair (`compare.rs`, #575) plus this one mix. A mix gone anyway (a cache cleared by hand) is rendered again by the timeline that finds it missing, once for each path (`Timeline.mixMissing.test.tsx`, `e2e/mix-evicted.spec.ts`). The slot's lock is taken alone, and the hold a replace or release hands back is dropped after unlocking it, because dropping a hold evicts (`release_window_mix` in "One live Store per project folder", `docs/agents/tauri-conventions.md`).

## Dialogs

- In the packaged app `window.confirm` is async (tauri-plugin-dialog's init script), so `if (!window.confirm(...)) return;` never returns and Cancel is ignored (#544). Always `if (!(await confirmAction(...))) return;` (`src/lib/confirmAction.ts`): it asks the plugin's `confirm()` inside Tauri and awaits `window.confirm` elsewhere, because in 2.7.x the swapped-in `confirm` asks for a `plugin:dialog|confirm` command the crate no longer registers. `window.prompt` is not polyfilled and macOS webviews return null, so the app asks for text in a box in the page (the label lane's name box, which the ruler's add-marker opens too, #548) and `noWindowPrompt.test.ts` fails a call to it.

## WaveSurfer, React and keyboard quirks

- `wsRef.current.zoom()` throws "No audio loaded" when WaveSurfer has no decoded data — always guard with `if (!wsRef.current || duration === 0) return` and include `duration` in the useEffect dep array.
- React's `onWheel` is passive in Chromium/Tauri — Ctrl+scroll requires `el.addEventListener("wheel", handler, { passive: false })` via useEffect, not the `onWheel` JSX prop.
- Window-level `keydown` listeners do NOT stop each other via `e.stopPropagation()` — guard with a state variable (e.g., `!showShortcuts`) instead.
- Keyboard shortcut handlers in App.tsx that should fire without audio must be placed **before** `if (!timelineRef.current) return`, not after.
