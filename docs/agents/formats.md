# Importable formats

Read before touching which audio files import: the decoders, M4A/AAC through the operating system, Opus.

- **Importable formats (#764)** are `audio_decoder::SUPPORTED_EXTENSIONS` (wav, mp3, flac, ogg, opus, aif, aiff: every platform), `audio_decoder::OS_DECODER_EXTENSIONS` (`m4a`: only where the operating system decodes it, `OS_DECODER_AVAILABLE`, macOS and Windows) the symphonia features in `crates/audio-decoder/Cargo.toml`, and `src/opus.rs`. `audio_decoder::supported_extensions()` is the list for the platform the code runs on; `batch_apply`'s folder filter reads it, and the window repeats the lists in `lib/importFormats.ts` (the picker, `lib/file-open.ts`, and the landing screen, `EmptyState.tsx`, both read it; the window decides from `navigator.platform` / the user agent whether the system decodes M4A: `/Mac|Win/`). `crates/audio-decoder/tests/supported_extensions.rs` fails if a copy differs or an entry of `supported_extensions()` has no decoding fixture on the platform it runs on, so the macOS and Windows legs of CI decode a real `.m4a`. **M4A/AAC is decoded only by the operating system's own decoder, and no AAC decoder is built into the app**: Via LA's AAC programme requires a licence of "manufacturers or developers of end-user encoder and/or decoder products", Audacity does not ship FFmpeg, its AAC route, "due to patent restrictions" (https://support.audacityteam.org/basics/installing-ffmpeg), and the project has no AAC licence on record, so the owner decided on issue #764 that macOS and Windows hand the file to the vendor's own licensed decoder. `crates/audio-decoder/src/os_aac/`: `macos.rs` uses AudioToolbox's Extended Audio File Services (`ExtAudioFileOpenURL`, a client format of interleaved 32-bit float at the file's rate and channel count, `ExtAudioFileRead`) through `objc2-audio-toolbox`, `objc2-core-audio-types` and `objc2-core-foundation` (0.3.2); `media_foundation.rs` uses Media Foundation's Source Reader and the Microsoft AAC decoder MFT (AAC-LC, HE-AAC v1/v2, up to 6 channels, 8 to 48 kHz; float output requested, rate and channels the decoder's own) through the `windows` crate (0.62, the version Tauri already pulls). Both are target-specific dependencies, so a Linux build pulls neither. **Windows looks Media Foundation up at run time** (`LoadLibraryExW` from System32 and `GetProcAddress` for `MFStartup`, `MFShutdown`, `MFCreateMediaType`, `MFCreateSourceReaderFromURL`; everything else is a COM vtable call): Windows N and KN editions ship without `mfplat.dll` and `mfreadwrite.dll` until the Media Feature Pack is installed, and a program that imports them does not start at all, so never call another `Win32::Media::MediaFoundation` free function (it would add a load-time import) and keep `Session` (COM and `MFStartup` per call, stopped on drop) around any use. A missing library or a failed `MFStartup` is `DecodeError::OsDecoderUnavailable` with the Media Feature Pack text; `MF_E_TOPO_CODEC_NOT_FOUND` (no decoder for this file's audio: AAC above 48 kHz or over six channels, AC-3 or Opus in an MP4, ALAC) is the same variant with a "Windows has no decoder for the audio in this file" text, and more than eight channels is `UnsupportedCodec`. `tests/no_media_foundation_imports.rs` lexes `media_foundation.rs` on every platform and fails on any `Win32::Media::MediaFoundation` free function outside the four looked up. A file is M4A/MP4 **by its bytes** (an `ftyp` box, `os_aac::is_m4a`), never by its extension, and only such a file reaches the system decoder (`decode_file`, `decode_bytes` through a temporary file, and `probe_sample_rate`, which decodes it, because clips never name an M4A: `load` makes a WAV of it). **Linux has no system decoder**, so an M4A/MP4 there still fails with `DecodeError::UnsupportedFormat("M4A and MP4")`, which names the format and says to convert (`load` says so to the model in its description). Not decoded anywhere: a bare `.aac` (ADTS) file. **Opus is decoded** (owner's decision on #764) although no published symphonia (0.5.5 or 0.6.1) has an Opus codec: symphonia's Ogg demuxer already yields the packets, and `src/opus.rs` registers a `Decoder` for `CODEC_TYPE_OPUS` beside symphonia's own (`codecs()` in `lib.rs`; `CodecRegistry::register_all`) that wraps `opus-decoder` 0.1 (pure Rust, `#![forbid(unsafe_code)]`, MIT OR Apache-2.0, 12 of 12 RFC 8251 vectors; chosen over libopus bindings to keep a C build out of the three installers). It is a young crate (two releases, March 2026), so every packet is decoded behind `catch_unwind` and a packet that fails stays in place as silence (in a shipped build too: the release profile unwinds, #908, and `opus.rs` refuses to compile under `panic = "abort"`); it decodes to 16-bit PCM, so an Opus import has 16-bit resolution (-96 dBFS floor), not libopus float's. Per RFC 7845 the output is always 48 kHz, the `OpusHead` pre-skip is dropped and its output gain (Q7.8 dB) applied by the decoder, and the end is cut to `last granule - pre_skip` frames read from the file's last Ogg page (`last_granule`; symphonia's own delay and padding for Opus are not used, they misread a one-page file), so a file's length is `ffprobe`'s less the pre-skip, to the frame. Only mono and stereo are opened (mapping family 0, or family 1 with a plain one- or two-channel table); surround, ambisonics and any other family fail with `DecodeError::UnsupportedOpusLayout`, which names the layout. A chained Ogg (two logical streams) or a damaged file is not end-trimmed. WebM/Matroska Opus is not opened (no `mkv` feature). Do not add symphonia's `aac` or `isomp4` features, FFmpeg, fdk-aac or faad2, or `m4a` to `SUPPORTED_EXTENSIONS`, without the owner's decision on the licence; whether calling the system decoder keeps the app outside "decoder product" status is a legal question that has not been answered. **Both systems return exactly the edit list's frames** (the fixtures: 22,050 and 24,000, asserted on each): macOS's ExtAudioFile trims priming and padding itself; Media Foundation does not, and returned every packet (23,552 and 25,600 measured in CI), so `media_foundation.rs` drops the priming (the gap between the frames decoded and the time the second sample starts at, the first's time being clamped to zero) and cuts the end to the source's `MF_PD_DURATION`, each only when under 8,192 frames. HE-AAC v1 and v2 are tested on macOS only, with files `afconvert` makes at test time (`he_aac_macos` in `tests/formats.rs`; CI fails if `afconvert` is missing); Windows has no stock encoder, so HE-AAC there is untested. The macOS and Windows code is built and tested only by CI's macOS and Windows legs (it is type-checked on Linux with shims, which is not a run). Fixtures are in `crates/audio-decoder/tests/fixtures/` with the ffmpeg commands that made them in its README (ffmpeg has no HE-AAC encoder, so only AAC-LC is covered).
