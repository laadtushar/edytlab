# Project audio, clip frames and rendering

Read before touching how the project names, writes, copies or deletes audio, a writer's destination, clip envelopes, seconds-to-frames conversion, session length, or what a render reports.

## Audio names and the AudioStore

- Audio the project writes under a name made from its samples is named by `audio_hash` (defined in `session::audio_store`, re-exported by `tools::provenance`; rate, channel count, then the samples) whichever writer wrote it: a destructive edit's output, a `load` copy, a clipboard blob, `generate_tone`, `generate_noise` (#620). `mix_to_new_track` is named by the blake3 of its WAV, header included, which holds the layout too. A file under a name is reused, not written, so a name that leaves the layout out hands one buffer another's file. Since #719 stage 2 every writer of new audio goes through `session::audio_store::AudioStore` (`put_with`; `put_verified` for a clipboard blob, which is replaced whole when it does not read back to its name; `put_named_by_content` for the mix-down, named by its WAV's bytes), and every name is an `AudioName` only `session` can make (`of_samples`, `of_lane` for a timeline lane copy). Since stage 3a every delete of the project's audio goes through it too: the orphan sweep, the history sweep, compaction and a killed repair's leftovers delete only a file `AudioStore::owns` places directly in one of its folders (a regular file, not a link and not a file in a folder below; the path's parent and the folder compared by identity, `session::live::identify`, never by spelling, so `derived/../../take.wav` is not one, and a volume that cannot canonicalise a path, such as ImDisk, vboxsf or WebDAV, still sweeps; compaction asks with the path already resolved, so a node naming a link in `derived/` to a regular file there lists the target, as before), and only through the `AudioDeleter` that `Store::audio_deleter` hands out while `Store::staged_in_flight` is zero, and never to a read-only store, and that asks again at each delete. Which folder each works in is unchanged (the sweeps and compaction `derived/` only, the leftovers `clipboard/` and `generated/`), so a clipboard blob or a generated file a pruned node names is still kept (#589). Since stage 3b the copiers and resolvers go through it as well: `rederive`'s put-back is `Rebuilt::put_back` (`AudioStore::rebuilt` reads what a replay wrote, and `put_with` writes it into `derived/` under the recorded name), repair's copies are `Counterpart::copy_in` (`Store::counterpart` now answers with a `Counterpart`, this project's place for another project's file; no-replace rename, the source's mtime, `.repair-*.wav.part` staging, whose killed leftovers in `clipboard/` and `generated/` `AudioDeleter::remove_copy_leftovers` removes), (a `Counterpart` is made only inside `session`, for the store's own project), a rebuild asks `AudioStore::folder_of` whether a gone file is in `derived/`, Save As's check (`needed_by_head`) asks `AudioStore::owns` for each head clip, in every folder, and `OwnedFile::in_project` for where the copy holds it, and Save As copies each store-folder file with `OwnedFile::copy_into` (staged in the copy's folder and renamed into place, so a Save As cut short never leaves part of a file under a trusted name). Since stage 4 the orphan sweep (`sweep_orphans`, `sweep_orphans_listed`, as a project opens) also removes a put's staging file (`.cas-*.wav.part`) left in `clipboard/` or `generated/`, but only once it is 24 hours old (`STALE_PUT_AGE`) and only through the `AudioDeleter` (`remove_stale_put_leftovers`: nothing while a handle is staged, the age and ownership read again at the delete; `SweepReport::removed_stale_staging`), because a punch-in writes its take there through `store_clipboard_blob` with no handle staged and no write there lasts more than a few minutes; one in `derived/` is an orphan at any age. The store's own cases (names, folders, puts, ownership, the deleter, copies, `Rebuilt`, the stale rule) are tested once, in `audio_store`'s module tests; `crates/tools/tests/audio_store/` is one test target holding what only its callers show, each test running tools (`legacy_names.rs`, `compaction_ownership.rs`, `copied_project.rs`, `reclaim.rs`: the sweeps, compaction, a rebuild, the repair). Stems (#385, stage 5) stay in `stem-cache/`, outside the store, and enter the project only through `load`, under a store name (`separate_stems_tool.rs`, `stems_enter_the_project_only_through_load_under_store_names`). `AudioStore::path_of` answers with a `StorePath` (`Display`, and `as_path()` for a read), never a `PathBuf`, so a store name cannot be handed to a writer; a writer uses the path its put returns. `tests/audio_names_cover_layout.rs` fails non-test code in `tools` or the desktop crate that hashes with blake3, spells a path into `derived/`, `clipboard/` or `generated/` (`*_dir(`, the `*_DIR` names, `AudioFolder::dir(..)`, `clipboard_blob_path(`), and non-test code in those crates or `session` that deletes a file (`remove_file`, `remove_dir`, `remove_dir_all`) or puts one in place (`persist`, `persist_noclobber`, `rename`, `hard_link`, `symlink`, `soft_link` as a method, a path or in a `use` group; `copy` after a segment with `fs` in it or in a `use` group of an `fs` path) more times than its allowance's exact count, unless its allowance says why it only reads or what it deletes or puts outside the store, and fails an allowance nothing uses. Edits and `load` copies share `.audiograph/derived/`, so an edit that reproduces a `load` copy names its file, which is right and which compaction and the sweeps allow for by asking which nodes name a path. Projects written before #620 named edit outputs and generated audio by the blake3 of the samples alone (`provenance::legacy_sample_hash`). Nothing is renamed, and names are compared, never recomputed from a file (it holds 16-bit PCM, not the samples as hashed): a replay (`rederive`, the history sweep's `Verifier`) counts the older name as a match for what it wrote and rebuilds under the recorded one, learning it from the clip's `content_hash` (the store's `Rebuilt` answers to both names, the file's and the older one), which an edit therefore keeps as the blake3 of its samples alone. `crates/tools/tests/audio_store/legacy_names.rs` builds such a project; keep the older-name match for as long as one can exist, and add no scheme field to stored ops for it.

## Destinations

- A writer that takes its destination from the caller never writes onto audio the project reads (#653). `load` leaves a WAV where it is, so the user's own recording is a clip source, and a render handed that path truncates it before it has read a sample (and a write that read first would still change what every older node plays). `tools::destination::refuse_project_audio(store, paths)` refuses a path that is the same file as any clip source named by any node (not only the head's) or the file a `load` read, compared by file identity (`session::live::identify`: device and inode, or volume serial and file id), never by spelling, so a symlink, a hard link or `take1.WAV` on a case-insensitive disk is caught. A path that does not exist cannot be a source, so only an existing destination costs a read of the history; an earlier export is still written over. `render_final`, `export_recipe`, `export_multiple` (by track and by region, every planned file before the first is written) and the window's `render_range` (Export Selection) call it. `batch_apply` also refuses, before it starts any file, a run whose `<output_dir>/<file name without its extension>.<render_format>` is an input in the folder (`destination::overlaps`; `output_dir` defaults to the input folder, so a render format equal to the inputs' extension collides), and the render of each file asks again. A new tool or command with an `out_path`, `output_dir` or save-dialog path calls it before it writes; `tests/render_over_source.rs` is the model.

## Clip envelopes

- A clip's `volume_envelope` is counted in the clip's own source frames (#677), like `start_in_track`, `source_offset` and `length`: `Clip::set_envelope` writes the points and marks `volume_envelope_frames` `Source`, and the renderer converts each point with `to_project_frames`. Envelopes saved before #677 carry no mark (`EnvelopeFrames::Project`, the default, skipped when serialised so every old node hash holds) and keep the only meaning the renderer ever gave them, project frames, because a stored envelope cannot say whether `set_clip_envelope` (project frames) or `duck_under_speech` (clip frames) wrote it. `util::load_head_state` converts a marked-`Project` envelope on an off-rate clip to `Source` once, so the slicers (`cut_timeline`, `split_at`, `merge_clip_envelopes`) only ever see clip frames. A new writer goes through `set_envelope`. `crates/tools/tests/clip_envelope_mixed_rate.rs` and `crates/audio-engine/tests/clip_envelope_frames.rs` pin it.

## Seconds, frames and session length

- A time in seconds becomes frames at the rate of the track it is applied to, never the session's, and the session's length is in session frames (#673, #678). A `Clip`'s `start_in_track`, `source_offset` and `length` are in the frames of its source file (#234), so tracks at different rates count one second in different numbers. A tool that turns seconds into clip frames (`cut_range`, `trim`, `split_clip`, `time_shift`, `split_by_speaker`, `punch_in`, `truncate_silence`, and sync-locked `insert_silence` and `paste_region`) asks `util::track_clip_rate` / `clip_source_rate` for it (`track_clip_rate`, used by `cut_range`, `trim` and the sync-lock helpers, refuses a track whose clips come from files of different rates); sync-lock hands every other track the same seconds in its own frames (`util::track_clip_rates`, `sync_other_tracks`), never one frame count for all. `SessionState::length_samples` is the furthest any clip reaches in session frames (each end converted from its clip's rate), written only by `util::set_session_length`, which a tool calls last: nothing adds to or subtracts from the stored number (#678). The renderer reads no stored length, so a stale value never changes a render. A new tool that cuts, shifts or splits goes through these helpers; `crates/tools/tests/clip_rate_mixed.rs`, `cut_words_mixed_rate.rs` and `length_samples_mixed.rs` are the models.

## Effects a render cannot run

- A stored effect the renderer cannot run (a kind that is not streamable yet, or one it does not know) never fails a render (#520, #531): `effect_chain::build` leaves it out as it does a bypassed one, and `skipped_effects` / `audio_engine::render_warnings` list it from the stored chains with no render. `RenderReport.warnings` carries the list, the render tools put it in a `warnings` array, and the window shows it (`get_render_warnings`, `RenderWarningsNotice`, #542). Only `gain`, `limiter` and the three filters stream; `add_effect` refuses the rest. A new path that renders has to report them too: leaving an effect out unannounced is the silent wrong output the old fail-the-render rule existed to prevent.
