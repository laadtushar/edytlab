# ML models: transcription, diarization, stems

Read before touching Whisper, speaker diarization, Demucs stem separation, a model download, or ONNX Runtime sessions.

## Status and model downloads

- Demucs and Whisper (`crates/ml-*`) are wired in as tools. **Transcription works end to end (`transcribe`, #384)** once the user has downloaded the speech model; **stem separation (`separate_stems`, #385) works once the user has downloaded the stem model** with the Stem model row in Settings → Account. Which release first carried each is in "Shipped in" (`docs/agents/ci-release.md`); describe the released app by that table. A verified, resumable model downloader (`ml_pipeline::fetched_model_path`) and the runtime gate below landed under #383, and three models are pinned (`whisper-base`, about 139 MB: three files of `onnx-community/whisper-base_timestamped` at a fixed commit, with size and SHA-256 each, in `crates/ml-pipeline/models.json`; `speaker-diarization`, below; and `htdemucs`, below). **The app downloads each only when the user clicks Download in Settings → Account** (`download_ml_model`, with Cancel, resume and Remove beside it, #383 PR 6); nothing downloads by itself, not at launch, not when Settings opens, not from a tool or the agent (the `transcribe` tool finds the model with `ml_pipeline::models::cached` and says it is not downloaded when it is missing, and never fetches it), and `crates/ml-pipeline/tests/only_the_user_downloads.rs` and `speechModelOnlyOnClick.test.ts` fail if another path could. The download runs on its own thread and holds no store, engine, dispatcher or agent lock, and keeps the model under `app_local_data_dir()/models` (not the roaming `app_data_dir()`). The Settings row says what the model is for (transcription, on this computer, once it is downloaded) and that the words it finds reach the AI provider like any tool result; only a model that is Ready is told to be used, and it never calls the model "enabled" or "installed". Describe every model download as started by the user's click (never automatically or on first use), and keep every copy of the privacy facts (GET requests to huggingface.co on the click, one per file and more on a retry; your IP address, the file requested and that edytlab, with its version in the User-Agent, is asking; no audio; no telemetry; transcribing makes no request, and the text of what was said reaches the provider as a tool result, not the audio) in step: the privacy page, the local-first table, the press kit. `htdemucs` is the only Demucs model id (`SUPPORTED_MODEL_IDS`, the `separate_stems` enum); `htdemucs_ft` and `DEMUCS_FT_MODEL_PATH` are gone (#547). The pieces of `ml-whisper` that need no runtime: the log-mel spectrogram (`mel.rs`, #554), the token decoder (`tokenizer.rs`, #555), the greedy decoding loop behind a `DecoderStep` trait (`decode.rs`, #556) and word timing from cross-attention with DTW (`timing.rs`, #557), each checked against the reference implementation.

## Speaker diarization

- **Speaker diarization (#168 section 2; the decision is a comment on that issue)** is `crates/ml-diarize`: pyannote.audio 3.1's segmentation and clustering pipeline with 3.0's ONNX frame-selection embedding, not 3.1's whole-window masked pooling (the pinned ONNX embedding takes no weights input; the port also samples above 3,000 embeddings, which 3.1 never does) (segmentation-3.0 -> a WeSpeaker ResNet34-LM voiceprint per speaker per 10 s window -> centroid agglomerative clustering -> turns) on two ONNX files pinned as ONE model, `speaker-diarization` in `crates/ml-pipeline/models.json` (32.5 MB: `onnx-community/pyannote-segmentation-3.0`, MIT, and `Wespeaker/wespeaker-voxceleb-resnet34-LM`, CC-BY-4.0, each at a fixed commit with size and SHA-256; the manifest lets a file name its own `repo`, `revision`, `source_path` and `license`, `CatalogModel::source_of`). Both repositories are public and not gated and the host is huggingface.co, the speech model's, so the privacy facts are the same ones; the original `pyannote/segmentation-3.0` is gated and is not usable by a click-to-download app. CC-BY-4.0 and MIT need their notices kept (Terms page). The model lives in `<models>/speaker-diarization/{segmentation,embedding}/model.onnx`; `DiarizeModel::load(folder)` checks each file's ports (`check_segmentation`, `check_embedding`) and builds sessions through `ml_pipeline::onnx_session::build`, never `Session::builder`. Neither network contains its pre- or post-processing, so the crate does it, each piece ported from pyannote.audio 3.3.2 / SciPy / Kaldi and held to `tests/fixtures/` (made by `make_fixtures.py` from `reference.py`, which copies pyannote's numpy functions verbatim and says so): `fbank.rs` (Kaldi 80-band fbank, mean-subtracted over the window, then the speaker's frames picked), `frames.rs` (the 17 ms output grid, speaker count, `reconstruct`, `Binarize`), `cluster.rs` (`linkage` with `method="centroid"` and `fcluster` numbered as SciPy numbers them, because tie-breaks follow the numbers; `SpeakerBounds` = `num_speakers` / `min_speakers` / `max_speakers`; above 3,000 embeddings only an evenly spaced sample is clustered), `pipeline.rs` (the two networks behind `Segmenter` / `Embedder`, so CI runs everything but the networks against recorded outputs). `num_speakers = 1` embeds nothing. Speakers are numbered by who speaks first. A speaker with no usable voiceprint (fewer than 9 filterbank frames, or `NaN`) is given cluster 0, as pyannote does. `tests/real_model.rs` (`#[ignore]`d, `DIARIZE_MODEL_PATH` + `ORT_DYLIB_PATH`, run by `ml.yml`) runs the real networks on 40 s of AMI (CC BY 4.0) and requires: every window's class as the reference's, every voiceprint at cosine 0.999 or better, turns within 1 % of the reference and DER against the human annotation under 25 % (14.8 % measured, 13.1 % with `num_speakers = 2`). **The `diarize` tool (#168 part 2; `crates/tools/src/tool/diarize.rs`)** runs it: `track` xor `path` (a track as it sits on the timeline, so turn times are session seconds; a file's are the file's), `num_speakers` / `min_speakers` / `max_speakers` into `SpeakerBounds`, the ONNX Runtime check before the model lookup, the model from `DIARIZE_MODEL_PATH` (a folder) else `models::cached(SPEAKER_DIARIZATION_ID)`, never downloaded by the tool. The audio is resampled with `ml_whisper::resample_to_16khz_mono`, and the turns are cached in the inference cache under the audio's `provenance::audio_hash`, the model fingerprint (pinned hashes, or a stat fingerprint of a developer's folder) and the bounds (bump `DIARIZE_FORMAT` when the pipeline changes). **It returns turns only and writes nothing**: no node, no markers, no label track, so `mutates()` is `false` (it is on `READ_ONLY`; the one thing it leaves is an inference-cache entry, which `read_only_tools.rs` allows) and the agent hands the turns to `split_by_speaker` (`[start_sec, end_sec, "speaker_N"]`, counted from 1 in the order they first speak), which is held for approval as an edit. It runs off the store lock with `progress` (`kind: "diarize"`, segmentation windows then voiceprints, the stage in the `file` label; `ToolProgressBar`'s allow-list has it), reads the cancel switch before every window and voiceprint, and bounds the listing to `RESULT_BUDGET_BYTES` (6,000; a longer conversation is cut off and the summary says not to split from the cut list). Its failure answers carry **no setup marker** (the setup card speaks of the speech model): they tell the agent to tell the user and stop. Tests run it against a `SpeakerModel` fake (`tests/diarize_tool.rs`). **Offered in Settings (#168 part 3):** a second row, "Speaker model", beside the speech model's in Settings → Account (`SpeakerModelRow.tsx`; `SpeechModelRow.tsx` and it are both `ModelRow.tsx` with their own words from `lib/speechModel.ts` / `lib/speakerModel.ts`, and `ModelRow.tsx` holds the one call of `downloadMlModel`). No new command: `ml_model_status`, `download_ml_model`, `cancel_ml_model_download` and `remove_ml_model` take the model id, and `speaker-diarization` is added to `OFFERED_ML_MODELS` in `commands.rs` (the allow-list `download_ml_model` checks before `start_download`; `only_the_user_downloads.rs` pins that order and that the list names exactly the offered models). The row says what it is for (who speaks when, on this computer, once downloaded), 33 MB in two files, and credits the MIT (pyannote segmentation, © CNRS) and CC-BY-4.0 (WeSpeaker) licences, also on the Terms page and in the user guide; the privacy page, the local-first table, the user guide and the press kit name the second model, with the same privacy facts as the speech model's. The row's words promise no tool: the `diarize` tool above is what uses the model, and the site copy shipped with v0.9.3 (#893).

## Stem separation

- **Stem separation (#385 PR 1; `crates/ml-demucs`)** is HT-Demucs v4 on ONNX Runtime. The model is pinned as `htdemucs` in `crates/ml-pipeline/models.json`: Intel's export (`Intel/demucs-openvino` at `efb3d2bc`, MIT; `htdemucs_v4/htdemucs_fwd.onnx` 2.4 MB and `htdemucs_fwd.onnx.data` 168 MB, 170.7 MB in all). The graph names its weights file, so the two are kept side by side under their own names, and `DEMUCS_MODEL_PATH` (the developer override) names that **folder**, not a file. **The graph is `HTDemucs.forward` with more cut out than the STFT and iSTFT**: the per-segment standardisation of both inputs and its inverse on both outputs are outside it too (`x` over all of its elements, `xt` over all of its, `(v - mean) / (1e-5 + std)` with torch's unbiased deviation, and `* std + mean` on the way out), and `htdemucs.rs` does them with the STFT and the sum `xt_out + istft(x_out)`; a graph fed an un-normalised spectrogram runs and returns numbers, so `htdemucs.rs` cites `htdemucs.py` and Intel's `htdemucs.cpp` (`_actually_run_model`) and `check_ports` refuses another export by name. Layers (the module table in `lib.rs`): `Network<Backend>` (the network, with a Rust function standing in for the graph in CI), `separate.rs` (the segment pipeline behind `SegmentModel`, **streamed**: `apply_model_streaming` hands each stretch of the four stems to a sink as soon as no later segment can change it, so what is held is one segment of every source whatever the track's length, and Cancel is read before every segment), `resample.rs` (`RateConverter`: rubato in pieces, no delay, the exact length), `pipeline::separate_to_dir` (a decoded file in, four 16-bit WAVs out in the file's own rate and length, mono for a mono file, the first two channels of a surround one; a value past full scale is clipped and counted), `cache.rs` (`Pending`: written in `<hex>.tmp-<pid>-<n>` and renamed only when all four are whole, so a cancel or a crash never leaves a partial cache hit; `prune` keeps `stem-cache/` under 1 GiB, least recently used first) and `DemucsModel` (one session behind a lock, built by `onnx_session::build`, so the execution provider is the `SessionOptions` of `load_with` and CPU is the default). **Speed and memory, measured on the 4 vCPU runner (release build, `ml.yml`)**: 1.6 to 1.7x realtime with the defaults (a 5-minute track in about 3 minutes; two cores' worth of threads, more gains nothing and one halves it), and the model's own working set is ONNX Runtime's, 2.7 GB at the peak for 102 s of audio and 3.0 GB for 306 s with `DemucsModel::session_options` (CPU memory arena and memory pattern both off: ORT's defaults peak at 5.0 GB and keep it until the session ends, the pattern alone costs 1.7 GB for nothing and the arena costs 15 to 25 % of the speed, 2.2 to 2.3x with it on, to hand memory back after a run; the process keeps about 2.4 GB resident afterwards, glibc not returning it); what this crate adds is the track's planar copy (106 MB per 5 minutes) and a segment. A computer with less than about 4 GB free cannot run it. It deliberately runs `shifts=0` (upstream's random shift would make the output depend on chance and the cache lie). Tests: everything but ONNX Runtime and the model runs in CI against fakes; `tests/onnx_split.rs` runs the pipeline on the real runtime with a committed model that has the pinned graph's ports and none of its network (`tests/fixtures/make_split_model.py`: every source is a quarter of the input); `tests/real_model.rs` separates a fixture mixed from known stems (`tests/fixtures/stems/`, CC0 and CC BY 4.0, credited in its README) and checks each stem's SDR (16.1, 19.7, 13.7 and 10.4 dB for vocals, drums, bass and other on the first run; the test requires 12, 16, 10 and 7), prints the realtime factor, and checks that the peak memory of a 102 s run and a 306 s run differ only by the longer input. Both run in `ml.yml`'s `stems` job, which is why it is a second job. PR 2 wired the `separate_stems` tool (`crates/tools/src/tool/separate_stems.rs`: `track` xor `path`, off the store lock with progress and Cancel, four stem WAVs in `<project>/.audiograph/stem-cache/`, a node-free answer the agent `load`s from; its failure answers name the Stem model row in Settings → Account, as `diarize`'s name the Speaker model row). **PR 3 is the Settings row** (`apps/desktop/src/components/StemModelRow.tsx`, words in `lib/stemModel.ts`, beside the speech and speaker rows, all three `ModelRow`): `htdemucs` is in `OFFERED_ML_MODELS` in `commands.rs`, and `only_the_user_downloads.rs` and `speechModelOnlyOnClick.test.ts` pin that the list names exactly the three models and that only Settings mounts the rows. The row's words credit the MIT licence (Demucs, © Meta Platforms, Inc. and affiliates; Intel's ONNX export, marked MIT) and the Terms page carries the same credit. **The site's privacy page, local-first table, user guide, tools and API data, and `marketing/press-kit.md` move with the release that ships it** (the site describes the released app), and name: the host and size (171 MB, two files, huggingface.co on the click, no audio), the 4 GB of free memory and half-the-audio's-length speed, and that the four stems are written into the project.

## Transcription

- **Transcription (#384)** is `ml_whisper::transcribe_observed` run by the `transcribe` tool (`crates/tools/src/tool/transcribe.rs`). `WhisperModel::load(folder)` reads the three pinned files (`WHISPER_MODEL_PATH` names that folder, not a file) and refuses a different export by name (`export.rs`); the merged decoder's key-value cache sits behind `DecoderStep` (`cached.rs`). **A window is decoded with timestamp tokens** (#659: `DecodeConfig::with_timestamps`, upstream's `ApplyTimestampRules`), and `segments.rs` ports what openai/whisper does with them (`transcribe.py`'s split at consecutive timestamps, and `timing.py`'s `add_word_timestamps`, cited at release 20250625): text that is not closed by an end timestamp is left for the next window, the words of the finished segments are aligned by running their text again as one sequence with `<|notimestamps|>` in the prompt (`CachedDecoder::alignment_attention`, upstream's `find_alignment`, because the attention of the timestamp-mode decode is not the one the aligner was built on), a word that ran on across a pause is cut back to about twice the median word, and the next window starts where the last word of the finished segments ended (`chunk.rs`; a window the model closed with a lone timestamp moves on whole; the advance has no floor but one frame, as upstream's seek has none, with a guard of this port's that makes the fourth small advance (0.5 s or less) in a row a whole window; a first word that is a repeat of the last is no longer special-cased; the loop guard compares text tokens only in timestamp mode, since timestamps only go up; word confidence is the alignment pass's, a softmax over the tokens under `<|endoftext|>`, as upstream's `find_alignment`). Long audio goes in 30 s windows (`chunk.rs`). Word edges are still pulled in to the sound (`refine.rs`, kept after measuring: the base model's segment timestamps run end to end and know no short lead-in, so it is what puts the first word of the fixture at 0.28 s and not 0.0 s, and it cut the worst word end from 1.1 s to 0.4 s on real speech with pauses put in it). `scripts/word-timing-eval` (`prepare.py`, `score.py`, and `cargo run --release -p ml-whisper --example word_times`) measures it on two LibriSpeech dev-clean chapters (CC BY 4.0, about 8 minutes each) against the Montreal Forced Aligner's word times: before #659 whole stretches of speech were missing (up to a fifth of a chapter, 20 s at a time), and since it 3.7% to 6.9% of the words are wrong, the median start is 0.065 s from the reference, 90% are within 0.16 to 0.19 s, and at most one matched word per recording is more than a second out (apart from one stretch the model hallucinated). It runs on the CPU, 3% to 28% slower than the notimestamps decode on those files (the timestamp tokens and the extra alignment pass). The tool: **`track` xor `path`**, as `analyze_track` (a track is read as it sits on the timeline, so word times are session seconds; a file's are the file's) and an optional `language`; the model comes from `WHISPER_MODEL_PATH` if set, else `models::cached`, **after** the ONNX Runtime check (a build with no runtime is not sent to download 139 MB). It runs **off the store lock** (`runs_off_the_lock`, on the `OFF_LOCK` list), and is the second tool allowed `progress` there (`ALLOWED` in `tests/off_lock_tools.rs`: `report` takes no lock, a lost race's re-run is a hit in the cache the first run filled, so its windows are not reported twice; `begin` and `cancelled` are the process-wide switch). The words are cached in the project's inference cache under `ContentHash::combine([provenance::audio_hash of the decoded input, the model's fingerprint (the pinned hashes, or a stat fingerprint of a developer's folder), the options and TRANSCRIPT_FORMAT])`; bump `TRANSCRIPT_FORMAT` when decoding changes. Cancel is read before every window and every decoder step, and a drop guard closes the progress strip however the run ends; `"transcribe"` is in `ToolProgressBar`'s `PROGRESS_KINDS`, an allow-list. **A transcript records where it came from** (`session::Transcript::source`: the track's id, or a file; defaulted and skipped when absent so node ids hash as before, `tests/transcript_source_hash.rs`), because its word times are seconds of that audio: `cut_words` and `remove_fillers` default to the transcript's track, refuse another, refuse a track that is gone, and need `track` for a transcript of a file (`util::transcript_edit_track`); the Transcript tab cuts only a track the transcript is of (`get_transcript` returns `{ words, source }`; `lib/transcriptSource.ts`) and says why when it will not. A tool that moves a track's clips by seconds (`time_shift`, `align_end_to_end`, `move_clip` for the words in the clip) moves those words by the same seconds through `util::shift_track_transcript` (#899); a clamped shift moves them by the clamp; the edits that cut, insert, stretch or re-speed audio remap it with the labels (`remap_after_cut` / `remap_after_insert` / `remap_after_scale`) only when its source track's audio moved (`util::Moved`: the edited track, or every track under sync-lock; #926): a transcript of another track is left alone, one of a file never moves, and one with no recorded source (older projects) follows every edit as before. Four setup problems answer with a **marker** (`MARKERS` in `transcribe.rs`, defined once): `agent_loop::extract_error_view` reads a marker at the start of a tool's error into `ToolView::SpeechSetup`, because the window is never sent a tool's error text, and `Chat.tsx` draws the card from the view, never from the assistant's words. No result or answer carries a local path (it goes to the provider); the result is a bounded listing (`RESULT_BUDGET_BYTES`, 6,000), and no speech found is an `Ok` that appends no node. Tests: CI runs everything but the model with a `SpeechToText` fake (`TranscribeTool::with`); `crates/tools/tests/transcribe_end_to_end.rs` (`#[ignore]`d, **fails** under `--ignored` without `ORT_DYLIB_PATH` and `WHISPER_MODEL_PATH`) runs the real model on `crates/ml-whisper/tests/fixtures/speech_words.wav`, then `cut_words` and `remove_fillers` on the real transcript. Measured through the tool on the real model, release build, on a shared four-core machine (`transcribe_end_to_end.rs`): the twelve known words, 0 wrong and every start within 0.22 s; 7 s of audio in 2.1 to 3.3 s the first time (model load included), 3 to 6 ms the second (the cache); `models::cached` 0.7 to 0.9 s to hash the 139 MB, and 0 ms the second time since it remembers a verified model by each file's size and modified time (it is not the check Settings makes, which always reads the files); a Cancel pressed in the first window lands in 0.4 to 1.3 s.

## ONNX Runtime sessions

- Build every production `ort` session through `ml_pipeline::onnx_session::build(path, options)`, which calls `runtime::ensure()` before any `ort` API and applies the requested thread count, optimization level and execution provider. The registry and Demucs use it; `ml-pipeline/tests/no_direct_session_builder.rs` guards the other crates and apps against direct builders. Keep the early `runtime::ensure()` calls in Whisper and `transcribe`, which select the setup error before model checks. With `load-dynamic`, `ort` 2.0.0-rc.13 returns an error from `ort::init_from` when it cannot load the ONNX Runtime library (rc.12 deadlocked there and in every other entry point), but its implicit load, which `Session::builder` and `ort::api()` do on first use, panics (tools run while the agent loop holds the store and engine locks, so it would poison them mid-turn), and a bare or relative path goes to the system loader's search instead of failing. `ensure()` finds the library by absolute path and checks it before `ort` sees it. It looks in `ORT_DYLIB_PATH`, then the bundle directory the app registers at startup (`runtime::set_bundle_dir`, once: `Contents/Frameworks` on macOS, Tauri's resource directory on Linux, none on Windows), then next to the executable; on macOS older than `min_macos` in `ml-runtime.json` it answers `RuntimeUnsupported` before opening the file. The `ml_runtime_status` command and the Settings line report what it found (`edytlab-desktop --ml-runtime-status` prints the same answer as JSON with no window). Every release installer since v0.7.0 (the first after v0.6.1) carries ONNX Runtime 1.23.2 and its notices (and on Windows the four VC++ runtime DLLs it imports, `vc_runtime` in `ml-runtime.json`), so an installed build says bundled; a build from source has none and says not installed in this build. That carries no model and runs no inference.
